La publicación utiliza imágenes de producción de Next.js y despliega el mismo commit aprobado por CI: primero las migraciones y Edge Functions de Supabase y después tienda, consola y repartidor en Railway. Cada imagen se comprueba sin red, con un puerto configurable y un endpoint de salud accesible sin sesión.

El CI utiliza Node 24, pnpm 11.6.0, Supabase CLI 2.120.0 y Ubuntu 24.04. Además, corrige bloqueos previos de permisos de ubicación, fixtures de fechas y retención, ordenación no determinista y lectura del reloj durante el render. La finalización del alta de Auth ahora lee app_metadata al terminar la transacción, porque la API administrativa completa esos metadatos después del INSERT inicial; las actualizaciones posteriores y user_metadata no cambian la aplicación asignada. También actualiza las pruebas del catálogo a los filtros actuales y al carrito de varias tiendas, y corrige nombres accesibles y contraste de dos etiquetas.

Validación local: tipos, actionlint, compilación de las tres imágenes y arranque HTTP, recursos estáticos, usuario sin privilegios y PORT=8080 sin red. Las regresiones SQL incluyen 11 comprobaciones de ordenación y 13 del alta de cuentas; además, se verificó el alta mediante la API real de Auth sobre el backend local. GitHub ya verificó las 1.634 pruebas SQL, el lint de base de datos, las 69 pruebas de funciones y el trabajo completo de frontend. Se regeneraron los tipos que detectó la última comprobación. La construcción de imágenes y las pruebas completas de operaciones continúan sobre un backend limpio.

El proyecto Rapitrip y los tres servicios vacíos de Railway ya tienen Dockerfile.production, dominios y comprobaciones de salud configurados. Asimismo, las variables de repositorio y el entorno production de GitHub están creados. Los tres secretos de production ya están guardados en GitHub y las variables públicas del proyecto Supabase remoto están verificadas y configuradas en los tres servicios de Railway. Antes de fusionar queda pendiente el resultado completo del CI. Los archivos .env locales quedan excluidos del paquete y de las imágenes. Los detalles de configuración están en docs/despliegue.md.
